# Test plan: projects

## projects.go

| ID | Function | Scenario Type | Scenario | Precondition | Expected Result | Priority | Notes |
|----|----------|---------------|----------|---------------|------------------|----------|-------|
| PJ-01 | getReleases | Happy Path | Token set, GitHub responds 200 with a valid JSON release array | a GitHub token is configured; GitHub answers 200 with a valid JSON array of releases | Returns the decoded releases and a nil error; the request goes to the releases of the group and project with the token as a bearer credential and an `Accept` header for GitHub's JSON media type | P1 |  |
| PJ-04 | getReleases | Error Path | the request to GitHub fails | a GitHub token is configured; the request to GitHub fails with a transport error | Returns no releases and an error that wraps the transport error | P2 |  |
| PJ-05 | getReleases | Error Path | GitHub responds 200 but body is not valid JSON | a GitHub token is configured; GitHub answers 200 with the body `not json` | Returns no releases and a JSON decoding error | P2 |  |
| PJ-06 | getReleases | Edge Case | GitHub responds 200 with an empty JSON array | a GitHub token is configured; GitHub answers 200 with an empty JSON array | Returns an empty, non-nil list of releases and a nil error | P3 |  |
| PJ-17 | getReleases | Error Path | GitHub answers 404 | GitHub answers with a 404 | Returns `nil`, `ErrReleasesNotFound` | P1 |  |
| PJ-18 | getReleases | Error Path | GitHub answers 403 or 429 | GitHub answers with a 403, then with a 429 | Returns `nil`, `ErrGitHubRateLimited` for each | P1 |  |
| PJ-19 | getReleases | Error Path | GitHub answers any other non-200 status | GitHub answers with a 500, then with a 401 | Returns `nil`, `ErrGitHubStatus` for each | P1 |  |
| PJ-20 | getReleases | Edge Case | Group and project contain URL-special characters | group "a/../b", project "p q" | The request path is /repos/a%2F..%2Fb/p%20q/releases; nil error | P1 |  |
| PJ-07 | ConvertToFMLFormat | Happy Path | Single release with a well-formed `"vX.Y"`-style tag | `releases = []Release{{TagName: "v1.20.1", URL: "https://example/1"}}` | The result has a `homepage` equal to the given URL; for each supported Minecraft version, `promos` holds a latest and a recommended entry equal to the release URL, and the version maps to `{"1.20.1": "https://example/1"}` | P1 |  |
| PJ-08 | ConvertToFMLFormat | Edge Case | Multiple releases with distinct tags | two releases, tagged v1.20.1 and v1.19.4, each with its own URL | The map of both versions to their URLs is the same under every supported Minecraft version (nothing is filtered per version), and the latest `promos` entries point at the URL of the first release | P2 |  |
| PJ-09 | ConvertToFMLFormat | Edge Case | empty releases slice | an empty list of releases | Does not panic; `homepage` is set, `promos` is empty, and every supported Minecraft version maps to an empty map | P2 | |
| PJ-10 | ConvertToFMLFormat | Error Path | release tag missing a "v" prefix | one release tagged 1.20.1 with the URL https://example/1 | Does not panic; the tag is used as it is, so every supported Minecraft version maps to `{"1.20.1": "https://example/1"}` | P2 | |
| PJ-11 | GetReleasesHandler | Happy Path | Request with no `format` query field, GitHub answers successfully | `group` and `project` path values set; a GitHub token is configured; GitHub answers 200 with a valid list of releases | Status 200, `Content-Type: application/json`, body is the JSON list of releases from GitHub | P1 |  |
| PJ-12 | GetReleasesHandler | Happy Path | Request with `format` set to fml, GitHub answers with one well-formed release | `group` and `project` path values set; the `format` query field is fml; a GitHub token is configured; GitHub answers 200 with one release tagged v1.20.1 | Status 200, `Content-Type: application/json`, body is the Forge update map (`homepage`, `promos` and one key per supported Minecraft version) | P1 |  |
| PJ-14 | GetReleasesHandler | Edge Case | Request with `format` set to fml, GitHub answers with an empty list of releases | `group` and `project` path values set; the `format` query field is fml; a GitHub token is configured; GitHub answers 200 with an empty JSON array | Status 200, body is the JSON map with `homepage` set to the project's releases page on GitHub and an empty `promos` object | P2 | |
| PJ-15 | GetReleasesHandler | Error Path | loading the releases fails for a reason with no dedicated response | a GitHub token is configured; the request to GitHub fails | 500 status, body is `msgFailedToGetReleases` followed by a newline; no cause text | P2 | |
| PJ-21 | GetReleasesHandler | Error Path | GitHub answers 404 | GitHub answers with a 404 | 404 status, body is `msgReleasesNotFound` followed by a newline | P1 |  |
| PJ-22 | GetReleasesHandler | Error Path | GitHub answers 403 | GitHub answers with a 403 | 503 status, body is `msgGitHubRateLimited` followed by a newline | P1 |  |
| PJ-23 | GetReleasesHandler | Error Path | GitHub answers 500 | GitHub answers with a 500 | 502 status, body is `msgGitHubBadStatus` followed by a newline | P1 |  |
| PJ-24 | GetReleasesHandler | Error Path | Writing the JSON body fails | the response cannot be written; run with and without the `format` query field set to fml | The handler returns without a panic | P2 |  |
